# agent-tcmedu-skills · 架构总览

> 版本 v0.1.0 ｜ 隶属 **tcmP 中医药网络教育平台** ｜ 定位：**教育技能亚项目**

---

## 一、一句话定位

**agent-tcmedu-skills 是 tcmP 平台的「教育能力层」**：把中医药教育场景（教材学习、经典研读、临床辨证、中药方剂、针灸推拿、骨伤五官、中医智能、中医管理、考试备考、师承带教、六者角色、医圣成长）封装成 Agent 可发现、可调用、可安装、可导出的结构化能力库，并以独立仓库、独立版本、独立 CI 的方式作为 tcmP 的亚项目持续演进。

它回答的是这样一个问题：

| 问题 | 答案 |
| --- | --- |
| tcmP 已有教材、图谱、六者 Agent、sage-api，还缺什么？ | 缺一层把「平台能力」翻译成「教育动作」的**契约层**——这就是本亚项目。 |
| 它与 hermes-edu-skills（K12 通用技能包）是什么关系？ | **同构不同域**：沿用其仓库范式（catalog + skills/ + 校验/导出工具链 + CI），但域换成中医药，且**与平台绑定**。 |
| 它与 tcmP 主仓是什么关系？ | **单向依赖 + 显式契约**：只读消费主仓的教材号 / 病证单位 / 平台接口，通过 `docs/02-与tcmP平台对接契约.md` 固化接口，不反向侵入主仓代码。 |

## 二、三环关系

```
┌──────────────────────────────────────────────────────────────────────┐
│  ① tcmP 平台层（已有，不属本亚项目）                                  │
│     · sage-api v2.0（35 路由）/ v3.0（45 端点，含 /icd /diag /rag）    │
│     · 病证知识图谱 DSU（60,000+ 节点）· 医圣 SOUL（张仲景 / 孙思邈）    │
│     · 120 门教材 · 8 域领域规范 · ICD-11 内网镜像 · 六者 agent 目录     │
└────────────────────────────┬─────────────────────────────────────────┘
                             │  被本亚项目「只读引用」
                             ▼
┌──────────────────────────────────────────────────────────────────────┐
│  ② agent-tcmedu-skills（本亚项目 · 教育技能层）                       │
│     · skills/<分类>/<slug>/SKILL.md   ← 42 个技能（12 分类）           │
│     · catalog.json / .well-known/skills/index.json  ← 机器可读索引     │
│     · scripts/{build-pack,validate,agent-pack}.mjs  ← 生成/校验/CLI    │
└────────────────────────────┬─────────────────────────────────────────┘
                             │  被 Agent 运行时「发现并加载」
                             ▼
┌──────────────────────────────────────────────────────────────────────┐
│  ③ Agent 运行时层                                                    │
│     · Hermes Agent（默认目标，skills.external_dirs 接入）             │
│     · 可导出：通用扁平包 / 其它 Agent 工具（见 export）                 │
│     · 终端：Web / 手机 APP（六者 CLI 映射）                            │
└──────────────────────────────────────────────────────────────────────┘
```

**关键设计**：② 层是**纯文档 + 纯工具链**，不含任何业务后端、不含用户数据、不含密钥。所有需要「算」的部分一律通过接口外呼 ① 层。这让本亚项目可以安全地公开、独立发版、被第三方复用。

## 三、边界：做什么 / 不做什么

| ✅ 做 | ❌ 不做 |
| --- | --- |
| 定义教育技能的结构化描述（触发信号、输入、工作流、产出、质量门禁） | 不实现问答的推理内核（由 LLM + 平台承担） |
| 固化与 tcmP 平台的接口契约（端点、角色、教材号、成长门禁） | 不复制平台数据（图谱、教材正文、患者数据不下沉到本仓） |
| 提供生成、校验、安装、导出、路由的 CLI 工具链 | 不接管平台部署与运维 |
| 维护 120 门教材 → 技能参数的映射规范 | 不重写教材本体 |
| 用 CI 保证「Spec ↔ 生成物 ↔ 发现索引」三者一致 | 不引入第二套事实源 |

## 四、仓库结构

```text
agent-tcmedu-skills/
├── package.json                        # bin: agent-tcmedu / agent-tcmedu-skills
├── catalog.json                        # ← 生成物：机器可读技能索引（42 条）
├── .well-known/
│   └── skills/index.json               # ← 生成物：发现索引（.well-known 规范位）
├── skills/                             # ← 生成物：Hermes 原生技能目录
│   ├── tcm-foundation/                 #   12 个分类目录
│   │   ├── tcm-basic-theory/SKILL.md
│   │   └── ...
│   └── ...
├── scripts/
│   ├── skills.spec.mjs                 # ★ 单一事实源（改内容只改这里）
│   ├── build-pack.mjs                  # 生成器：spec → skills/ + catalog + index
│   ├── validate.mjs                    # 校验器：一致性 / 敏感模式 / spec 同步
│   └── agent-pack.mjs                  # CLI：list/search/info/match/ask/prompt/doctor/install/export

├── .github/workflows/validate.yml      # CI：build → validate → 生成物已提交
├── HERMES.md                           # ← 生成物：项目级启动 Prompt
├── README.md / README.en.md
├── CHANGELOG.md / CONTRIBUTING.md / RELEASE.md / SECURITY.md
└── LICENSE (MIT)
```

> ★ 标记 = 唯一需要人工编辑的文件。其余带「生成物」标记的文件一律禁止手改，改内容请改 spec 后 `npm run build`。

## 五、单一事实源与生成管线

```
   scripts/skills.spec.mjs            ← 人写：分类定义 + 42 条技能内容 + 平台 API 登记表
              │
              │  npm run build   （scripts/build-pack.mjs）
              ▼
   ┌──────────────────────┬──────────────────────────┬────────────────────┐
   │ skills/**/SKILL.md   │ catalog.json             │ .well-known/.../    │
   │ （Hermes 原生格式）   │ （机器可读索引）          │   index.json        │
   └──────────────────────┴──────────────────────────┴────────────────────┘
              │
              │  npm run validate （scripts/validate.mjs）
              ▼
   ① 三者计数/路径/名字一致  ② frontmatter 完整（source / author / 质量门禁 / 平台对接）
   ③ 无敏感模式            ④ spec 与 catalog 顺序一致（防「忘记 build」）
```

**为什么用生成器而不是手写 42 个文件？**

1. **一致性可证**：索引与技能文件不可能漂移——它们同源。
2. **规模可扩展**：v1.0 目标是把 120 门教材全部映射为技能参数，手写不可持续。
3. **可自动化校验**：CI 能判定「生成物是否已提交」，人改生成物会立刻红灯。
4. **这本身就是一次流程优化**：把「多文件手工同步」这一重复性、规则明确的任务自动化——正是本亚项目存在的理由。

## 六、与 tcmP 主仓的关系

| 维度 | 约定 |
| --- | --- |
| 依赖方向 | 本亚项目 → 主仓（**单向**）。主仓不依赖本亚项目。 |
| 复用方式 | **只读引用**：教材号（CM-01 / MM-01 / AT-01…）、领域编号（D01–D08）、病证单位（DSU）、平台端点。 |
| 契约载体 | `docs/02-与tcmP平台对接契约.md`——任何接口变更必须同步此文档，并触发本亚项目小版本号 +1。 |
| 数据下沉 | 禁止。图谱数据、教材正文、患者数据、任何密钥都不得进入本仓。 |
| 主仓事实源 | `~/textbook-project/domain-specs/DOMAIN_SPEC_D0*.md`（8 域 / 120 门学科 / 6738 行） |
| 主仓接口实现 | `~/textbook-project/sage-api/main.py` |

## 七、独立发展机制

| 机制 | 实现 |
| --- | --- |
| **独立仓库** | 独立 git 仓、独立 README、独立 LICENSE，不寄生在主仓目录树下。 |
| **独立版本** | 语义化版本，与平台 vN 号解耦；仅通过契约文档建立对应关系。 |
| **独立发布通道** | `package.json` 的 `files` 白名单 = 发布内容边界；可直接 `npm publish` 或打包分发。 |
| **独立 CI** | `.github/workflows/validate.yml`：build → validate → 生成物已提交 三关。 |
| **独立消费方式** | 三种：① 接入 Hermes（`install hermes`）；② 导出扁平包给其它 Agent（`export generic`）；③ 直接读 `catalog.json` 做程序化集成。 |
| **扩展点** | 加技能 = 在 spec 追加一条；加分类 = 在 `CATEGORIES` 追加一项；加接口 = 在 `PLATFORM_APIS` 登记（未登记会被 build 直接拦截）。 |
| **变更安全** | 未登记的 API 会被 `build-pack` 的完整性检查拒绝；敏感模式会被 `validate` 拒绝；生成物漂移会被 CI 拒绝。 |

## 八、质量门禁

技能内容本身必须通过以下门禁（已写入每个 SKILL.md 的「质量门禁」章节，并被 `validate.mjs` 校验其存在）：

1. 每条结论必须可回答「依据是什么」——教材章节 / 病证单位 / 平台接口返回。
2. 依赖平台接口的结论必须标注来源端点；接口不可达时标注「未能核实」。
3. 涉及患者安全的输出必须携带边界声明与就医提示，**不输出处方剂量**。
4. 输出必须可验收：给出可自查的完成标准，而非「已了解」。

仓库层面门禁：见第五章的生成管线 + 三道校验——① `validate.mjs`（一致性 / frontmatter / 敏感模式 / spec 同步）、② `check-docs.mjs`（文档技能表与 catalog 同步）、③ CI 的「生成物必须已提交」。任一条不过，提交即被拒。

## 九、关键命令

```bash
npm run build          # 从 spec 生成 skills/ + catalog.json + 发现索引
npm run validate       # 一致性 / 敏感模式 / spec 同步 校验
npm run verify         # build + validate

node scripts/agent-pack.mjs list                        # 列出全部技能
node scripts/agent-pack.mjs list tcm-role-agents        # 按分类列出
node scripts/agent-pack.mjs search 辨证                  # 关键词搜索
node scripts/agent-pack.mjs info role-healer            # 技能详情
node scripts/agent-pack.mjs match "少阳病的经方" --top 5  # 自然语言匹配
node scripts/agent-pack.mjs ask   "帮我做病案辨证训练"     # 匹配并调用 Hermes
node scripts/agent-pack.mjs prompt --target ./HERMES.md  # 生成启动 Prompt
node scripts/agent-pack.mjs doctor                      # 体检
node scripts/agent-pack.mjs install hermes --apply      # 接入 Hermes
node scripts/agent-pack.mjs export generic --target ./dist/agent-skills
```
