## 三、M1 — 接入 Hermes（v0.2.0）

**目标**：让技能真正被 Agent 用起来。

| 任务 | 产出 | 验收 |
| --- | --- | --- |
| 接入 Hermes 配置 | `skills.external_dirs` 指向本仓 `skills/` | `hermes skills list` 显示 42 个技能 |
| 部署启动 Prompt | 项目/全局 `HERMES.md` | 教育类提问先检索本技能包 |
| 真实任务回归 | 3 类任务各 1 例（学科同步 / 平台能力 / 六者角色） | 记录任务 → 命中技能 → 输出的完整链路 |
| 路由准确率基线 | `match` 的 Top-1 / Top-3 命中率 | 建立 50 条中文教育问题的评测集，Top-3 命中率 ≥ 80% |

**风险**：中文自然语言路由的召回调优（当前为规则打分 + 二元组回退）。缓解：先建评测集，再决定是否引入向量化路由。

## 五、M3 — 平台双向闭环（v0.8.0）

**核心理念**（继承 tcmP 的 CI/CD 人机闭环）：**每次对话都是进化信号**。

```
用户提问 → 技能被命中 → 调用平台接口 → 产生输出
    │                                        │
    │                                        ▼
    │                              ┌──────────────────┐
    └──────────────────────────────│ 反馈采集（可选）  │
                                   └────────┬─────────┘
                                            ▼
                            日志 → 图谱 → Agent 调优 → 自动上线
                                            │
                                            ▼
                                  反向修正教材与技能参数
```

| 任务 | 产出 |
| --- | --- |
| 技能调用埋点规范 | 记录 `skill_hit` / `api_call` / `api_fail` / `user_feedback` 四类事件 |
| 命中率与失败率看板 | 接入平台 `/regulators/dashboard` 或独立看板 |
| 失败归因流程 | 区分「技能描述不准」/「路由不准」/「平台接口不可用」 |
| 技能迭代节奏 | 每月一次基于埋点数据的技能修订 |
